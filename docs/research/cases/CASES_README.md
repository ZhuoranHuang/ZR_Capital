# owner_rule_2 交易案例图（正股视角）

生成：`uv run python -m zr.research.case_charts`（`zr/research/case_charts.py`）。入口：`docs/research/cases/index.html`；

## 规则

- 入场：owner_rule_2（`config/intrabar/owner_rule_2.yaml`，R-049 预登记）触发的时刻。三个条件（方向化）：1 分钟
  MACD(6,13,6) 柱在交易方向一侧（≥ 0）；近 10 分钟正股朝交易方向涨跌 ≥ 0.141%；所买方向平值期权中间价 60 秒变化
  ≥ −0.38%。入场时段 09:32–15:40，同方向 5 分钟内不重复，同一时间一笔。
- 出场时刻：R-052 选定组——期权中间价相对买入价 +6.5% 止盈 / −30% 止损 / 30 分钟上限，负责人挂单策略卖出；15:50
  （0DTE 10:45，D-001）清仓。合约 = 最近到期日虚值一档（10:15 后不用 0DTE）。只保留期权实际成交的信号。期权只用来
  确定出场时间。
- 价格与盈亏：入场价 / 出场价 = 入场 / 出场时刻的正股价；盈亏 = 正股朝交易方向的涨跌（%）。等于 0 的不计。
  出场原因按期权规则记录（止盈 / 止损 / 到时 / 清仓），所以会出现「期权止盈但正股略亏」的情况。

## 数据与日期范围

- MU：2026-02-01～2026-04-28（R-052 第 2 步的落盘交易，负责人挂单执行）。正股价 = 秒级看跌看涨平价反推价；期权 = 本地
  逐笔缓存。2026-04-29 之后没有期权逐笔缓存（预取已中止），所以 MU 的最近 10 笔全部落在 2026-04-28 一天。
- QQQ：2026-09-01～2026-10-21。本地没有 QQQ 秒级正股价与期权逐笔 → 用 1 分钟 K（已完成 K 的收盘）作正股价、本地
  1 分钟期权报价（options_1m）作期权，在分钟网格上复现 owner_rule_2 的三个条件与 R-052 出场；盘口由 1 分钟报价构造，
  只有报价越过挂单价才成交（比 MU 的逐笔引擎保守）。入场 / 出场时刻落在整分钟，出场正股价取出场时刻前最后一根已
  完成 1 分钟 K 的收盘。
- 排除 2026-06～08（D-033 校准窗口）。不拉新的期权数据。

## 选取方法

每个标的取盈利最近 5 笔、亏损最近 5 笔（按入场时间倒序，不挑选），共 20 笔；两个标的都足够，没有向前扩展月份。
